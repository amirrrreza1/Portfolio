# M4 root negotiation and public UI catalogs

Run date: **2026-08-14**

## Delivered boundary

- The bare `/` request resolves locale in the required order: validated
  `portfolio_locale` cookie, then quality-weighted `Accept-Language`, then the
  English default.
- Regional `en-*`/`fa-*` tags, quality ordering, `q=0` exclusions, unsupported
  languages, malformed/oversized input, and a tampered cookie are bounded by a
  pure allowlisted resolver.
- The root response is a one-hop `308` and alone carries
  `Vary: Accept-Language, Cookie`. Explicit locale-prefixed routes do not
  negotiate or redirect.
- The settings dialog switches the current equivalent route rather than
  returning to home, writes a one-year `SameSite=Lax` non-personal locale
  preference when JavaScript is available, and remains a normal locale link
  when JavaScript is disabled.
- Versioned `en.json` and `fa.json` catalogs now drive the active portfolio
  shell, appearance dialog, project list/detail, certificates, resume,
  contact form/toasts, outage views, footer, and localized not-found page.
- TypeScript enforces missing catalog groups/keys; tests enforce exact key
  parity, non-empty strings, and rejection of HTML-bearing values. Catalog
  values enter React as text, never as HTML.
- Visitor-facing counts use locale number formatting. Certificate and project
  dates retain Gregorian ISO `datetime` values while Persian visible dates use
  the Persian calendar.

## Production-mode run

A production build using the explicit legacy rollback source succeeded. The
built server then ran with an unreachable API origin so the proof did not
depend on the database API.

Root requests produced:

| Request state                                    | Result    |
| ------------------------------------------------ | --------- |
| No cookie or language header                     | `308 /en` |
| `Accept-Language: fa-IR,fa;q=0.9,en;q=0.2`       | `308 /fa` |
| `portfolio_locale=en` plus `Accept-Language: fa` | `308 /en` |
| Invalid locale cookie plus `Accept-Language: fa` | `308 /fa` |

Every root redirect carried the reviewed security headers, `private, no-store`,
and `Vary: Accept-Language, Cookie`.

Requests to `/en/projects` with a Persian preference and `/fa/projects` with an
English preference both remained on their explicit paths and returned `200`.
Their initial HTML carried the matching `lang`/`dir`, catalog heading, and
catalog search placeholder. The Persian page did not contain the English
equivalents of those UI strings.

The initial HTML for `/fa/projects/portfolio` contained the Persian language
control and an ordinary `href="/en/projects/portfolio"`, proving equivalent-page
switching and a no-JavaScript navigation path.

- Routing tests cover cookie precedence, regional tags, quality ordering,
  exclusions, unsupported-language fallback, current legacy redirects,
  explicit-prefix stability, `Vary`, cookie serialization, and equivalent path
  switching.
- Catalog tests cover exact key parity, non-empty text, no HTML values, locale
  selection, Persian digits, and Persian-calendar formatting.
- The complete web suite passed **64 tests across 14 files**.
- The complete workspace passed **470 tests across 43 files** in all nine tested
  apps/packages, and all nine TypeScript checks passed.
- API and web ESLint passed. The API configuration now deliberately keeps
  type-aware linting on production source while applying non-type-aware
  TypeScript rules to its test doubles and JavaScript config file.
- API and Next.js production builds passed; the Next.js build retained the bare
  root, localized home, project list, and per-slug project-detail routes.
- Repository-wide Prettier and `git diff --check` passed. All **286** relative
  links across **34** documentation files resolved.
