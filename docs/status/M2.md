Status: **In progress**

Depends on: M1 complete

## Outcome so far

The migration has now been applied to PostgreSQL 17 and a private MinIO bucket. Six PDFs were verified and written, all database/content counts reconcile, stored-object hashes match source/database metadata, and immediate replays skipped without creating objects. Projects, skills, certificates, quotes, the active resume, localized shell, appearance settings, exact Hero/About prose, private age derivation, and ordered/disabled page sections have now been exercised successfully in database and isolated legacy modes. All six API-delivered PDFs matched the frozen legacy bytes. Only three owner-selected accessible colour replacements and the resulting reviewed normalization version keep the exit gate open.

## Delivered

- Versioned legacy snapshot loader and deterministic source checksum.
- Validation for 14 projects, 6 skill categories/26 skills, 5 certificates, 35 quotes, resume/media, links, statuses, relations, and path casing.
- Reviewed normalization: placeholder project URL becomes null; unknown enums and orphan relations fail.
- Reconciliation report with explained warnings, including three `#000000` skill colours requiring owner choices.
- Transactional writer and Prisma adapter requiring verified media references.
- Explicit-apply CLI that skips a matching replay and removes newly created objects after database-transaction failure.
- Legacy JSON reads isolated behind `apps/web/src/server/legacy-portfolio.ts` for later rollback switching.
- A server-only `PORTFOLIO_DATA_SOURCE` switch now selects either the database API or legacy adapter for `/[locale]/projects`; a live rollback run rendered both locales while the configured API origin was deliberately unreachable.
- The same switch now controls localized navigation, site settings, section metadata, and footer links; distinct database and legacy link sets proved which source rendered while rollback remained independent of the API.
- The switch also controls the root appearance allowlist; database and API-independent legacy runs produced the expected locale-compatible themes, fonts, sizes, and first-response defaults.
- The localized homepage now reads projects/skills through the proven projects client and quote/certificate/resume metadata through a strict `home` client. Database HTML carries opaque document routes while rollback HTML carries only the legacy static paths.
- A separately versioned `2026-08-14.page-sections.1` migration replaces the deliberate Hero/About seed placeholders with the exact frozen English source, moves the private birth date into `SiteSettings`, restores the legacy six-section render order, and records no private date in its report.
- Hero/About prose now uses the restricted inline-Markdown profile, derives age in UTC inside the API, falls untranslated Persian fields back to English, and exposes neither the date nor raw template token.
- Live database and API-independent rollback pages matched all three Hero strings, both About paragraphs, strong/emphasis semantics, and section order. A temporary database disable removed the contact section from API and rendered HTML while adjacent sections remained; the row was restored immediately.
- API-mediated reads from the private MinIO bucket reproduced all five certificate PDFs and the active resume byte-for-byte; the DTOs expose no bucket, credential, storage key, checksum, or media ID.
- Real apply wrote 14 projects, 6 skill categories, 26 skills, 5 certificates, 35 quotes, 55 project-skill relations, one active resume, and six verified media rows.
- A separately versioned M4 configuration migration derived the exact 13-repository GitHub statistics allowlist from those frozen project URLs, applied once, and skipped on replay without changing the frozen source.
- Private MinIO reconciliation proved six stored objects have the exact source/database byte sizes and SHA-256 hashes.
- A second identical run performed no database migration and wrote no new object.
