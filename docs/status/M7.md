## Delivered

**The authenticated `/admin` surface**, covering every non-blog resource
family: site settings and per-locale site text, appearance, page sections,
navigation, social links, skill categories and skills, projects with ordered
skill relations, certificates, quotes, media, resume versions, explicit
archive/restore, revisions with restore, audit events, sessions, and users.
Every mutation runs a session check, CSRF and origin validation, `If-Match`
optimistic concurrency, and answers `private, no-store`; every successful write
records a versioned revision, a redacted audit event, and durable locale-scoped
invalidation events in the same transaction.

**The admin workspace**, in four panels — site and structure, portfolio
collections, media and resume, history and access — with accessible loading,
empty, error, and conflict states. A stale save is refused in the UI with a
conflict message rather than silently overwriting, proven with two browser
contexts editing the same record.

**ADMIN-003's dashboard**, exposing only safe counts and event categories:
drafts, scheduled translations, retained contact messages, recent edits, failed
security events, and the publication/invalidation queue state. No bodies, audit
metadata, credentials, storage keys, or client fingerprints.

**Media and resume.** Uploads are bounded before parsing, typed by magic bytes
rather than by filename or client MIME, images are decoded and re-encoded,
PDFs are page- and policy-checked, and anything refused is quarantined under a
random key rather than discarded. Storage keys never appear in any DTO.
Activating a resume version retires the previous one in the same transaction,
and the public download stays on one stable path.

**The last authored copy moved out of the source.** SEO keywords and metadata,
footer lines and rights text, the resume button label, and all thirteen
contact-form strings now come from the database per locale. `app/layout.tsx`
keeps only `metadataBase`, which stays an environment concern.

## Two defects the live run found

1. **A project authored without its English translation returned `500` for the
   whole locale**, and the public site went to `503` behind it — the M4
   articles defect repeated in a different resource family. Collection reads
   now exclude an unrenderable record and log it; the detail path answers
   `404`. `PublicHomeService` had the same fault for certificates twice over.
2. **`isRoleAssignable` was not wired to the endpoints that grant roles**, so
   `POST /admin/users` could hand out `EDITOR` while `DECISIONS.md` and the
   module's own comment said it must not be. Both user endpoints now call it.

Details, including why neither was visible to any unit test, are in the
evidence file.
