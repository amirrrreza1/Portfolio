# M3 — PostgreSQL-native article foundation

Status: **Complete**  
Snapshot: **2026-08-26**  
Depends on: M1 and M2  
Roadmap: [M3 definition and exit gate](../ROADMAP.md#m3--postgresql-native-article-foundation)
Normative decision: [ADR-015](../DECISIONS.md#adr-015--postgresql-native-article-authoring-and-publication)

## Current position

PostgreSQL is the sole authority for article translations: Markdown source, editorial metadata, publication state, integer versions, immutable revisions, and a render cache bound to its source by a SHA-256 digest and a renderer version. MinIO holds binary media and nothing else.

The previous Git-backed M3 implementation and its 2026-08-24 live run are superseded architectural history. GitHub App authentication, content-branch protection, inbound content webhooks, synchronization/drift states, apply ledgers, operation records, and cross-system reconciliation are gone from the schema, the runtime, and the configuration — removed, not disabled.

## Delivered

- Forward migration `20260825120000_postgres_native_articles`: adds `bodyMarkdown` and `bodySha256`, replaces the draft blob token with an integer `baseVersion`, drops the Git synchronization columns, tables, and enum types, and rebuilds the render-provenance and published-has-source constraints and the public partial indexes around the new source columns.
- Safe treatment of legacy indexed rows: the migration demotes every row with no recoverable Markdown to `DRAFT`, `post_translations_published_has_source` stops it returning to `PUBLISHED`, and the public partial indexes exclude it. Nothing reconstructs source for such a row.
- Server-only transactional article repository (`packages/database/src/articles.ts`) validating locale and editorial identity, existing taxonomy references, deliverable media, production Markdown rendering, source digests, and the expected translation version.
- Atomic persistence of source, metadata, sanitized render cache, translation version, immutable revision, audit event, and signed-invalidation outbox intent in one transaction. A stale version or any failure writes nothing.
- PostgreSQL-backed scheduled publication: `enqueueDuePublications`, the `PUBLISH_DUE` queue with `FOR UPDATE SKIP LOCKED` claims and bounded retries, the advisory-lock scheduler, and idempotent `publishDueTranslation`.
- Unit coverage for bilingual saves, stale-version conflicts, the media predicate, single-transaction discipline, digest mismatch, premature publication, and enqueue accounting (`packages/database/test/articles.spec.ts`).
- A committed, re-runnable exit-gate verification, `packages/database/scripts/verify-article-authority.ts`, exposed as `pnpm --filter @portfolio/database verify:articles`.

## Exit gate

Every condition is met, with the live run as its evidence.

| Exit condition                                                                                    | Where it is proven                                                                |
| ------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| Complete bilingual Markdown, valid SHA-256 digests, current safe renders, metadata, and revisions | §1, §2, §7 — digests recomputed by PostgreSQL rather than by the writer           |
| A stale version or invalid body/reference changes neither the article nor its revision/outbox     | §3 — a full-state snapshot compared before the first rejection and after the last |
| A forced transaction failure leaves source, render, revision, and invalidation state unchanged    | §4 — a real constraint violation and an injected post-write failure               |
| Due publication is idempotent and requires neither Git access nor deployment                      | §6 — replayed publication is a no-op, run with HTTP egress sealed and counted     |
| No Git credential, webhook, synchronization model, or recovery worker in the active runtime       | §0, plus `apps/api/src/config/environment.ts` and the removal of `rawBody`        |

The run found one blocking defect: the media reference check filtered `media_assets` on a column that does not exist, so any article carrying a cover or social image was unsavable. It is fixed, and the unit suite now asserts that predicate rather than mocking it away.

## What M3 deliberately does not cover

Rendering a published article on a public route, and running publication invalidation end to end through that route, are M4's gate. The authenticated editor, import/export, and publishing UX are M8's. M3 stops at the authority boundary: the rows are correct, and nothing outside a server process can write them.
