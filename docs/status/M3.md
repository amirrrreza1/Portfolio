# M3 — Git content-store proof

Status: **In progress**  
Snapshot: **2026-08-14**  
Depends on: M1 and M2  
Roadmap: [M3 definition and exit gate](../ROADMAP.md#m3--git-content-store-proof)

## Outcome so far

The content-store package contains the core secure transport, reconciliation, and durable recovery primitives. The milestone still needs a real protected branch, API worker integration, a bilingual direct push, and cross-system failure drills.

## Delivered

- GitHub App installation-token exchange/cache and server-only runtime validation.
- Dedicated `content` branch and `content/` prefix enforcement with normalized safe paths.
- Blob-SHA optimistic concurrency and safe fixed commit metadata primitives.
- Signed webhook verification, replay-claim persistence, and trigger-only webhook handling.
- Git-tree reconciliation through the production Markdown renderer.
- PostgreSQL apply ledger/outbox schema and adapter for idempotent recovery.
- Unit/boundary coverage for traversal, unsafe writes, configuration, webhook/reconciliation behavior, and database boundaries.

## Outstanding gate work

- Configure a real GitHub App and protected `content` branch with force-push/deletion prevention and secret scanning.
- Integrate durable jobs/reconciliation into a dedicated API worker process.
- Add one real article in English and Persian by direct push and reconcile it into PostgreSQL/render cache.
- Force Git-success/database-failure and invalidation-failure cases; prove convergence without duplicate revisions.
- Prove invalid/deleted content preserves the previous live render and reports drift.
- Prove Git outage blocks authoring only, never public reads or database-driven publication.
