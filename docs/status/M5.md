# M5 — Appearance and accessibility

Status: **In progress**  
Snapshot: **2026-08-16**  
Depends on: M4 shell/public read path  
Roadmap: [M5 definition and exit gate](../ROADMAP.md#m5--appearance-and-accessibility)

## Outcome so far

The server-resolved preference shell now consumes the locale-scoped owner allowlist from PostgreSQL through the strict public API, with an explicit legacy rollback source, bounded validated fallback, and a real localized HTTP `503` when no allowed value exists. The accessible settings UI, CSP pre-paint path, and reduced-motion wiring are present, and the THEMING §3 token vocabulary is now adopted, enforced in CI, and passing a 26-pairing WCAG 2.2 AA matrix in both themes. Font delivery and the browser half of the verification matrix remain incomplete.

## Delivered

- Strict `portfolio_prefs` contract and allowlisted theme/font/size/motion registry.
- Cookie-resolved `data-theme`/`data-motion` attributes in the initial server response.
- Blog typography scoped to `.blog-reading-surface`.
- Reviewed nonced pre-paint path for `system` mode and public security headers.
- Accessible settings dialog for appearance, typography, motion, and language.
- Reduced-motion wiring across hero, particles, scramble text, typing text, smooth scroll, and related effects.
- Inline application styles removed.
- The THEMING §3 token vocabulary declared per theme, with `--color-success`, `--color-particle`, and `--color-scrim` as documented extensions; 106 colour utilities across 22 files migrated; every opacity-thinned text and border variant replaced with a measurable token.
- Five WCAG 2.2 AA failures the shared-value palette had hidden are fixed: muted text at 2.60:1 on light, Gold at 1.75:1, green at 2.28:1, red at 4.47:1 on dark, and the placeholder grey at 4.34:1 on dark.
- Three `dark:`-variant colour switches removed. No `@custom-variant dark` is declared, so they resolved against `prefers-color-scheme` rather than the selected `data-theme` — the tooltip rendered white on white for a dark-theme visitor on a light operating system, and the footer's social links went invisible on hover.
- The Skills category card no longer paints 60% of the foreground under foreground-coloured chips, which was 2.2:1 on dark and 3.3:1 on light.
- The two `prefers-color-scheme` fallbacks scoped `:not([data-system-theme])`, so the media fallback and the script-resolved attribute can no longer both apply.
- CI enforcement against raw colours, Tailwind palette utilities, retired token names, stale allowlist entries, and stylesheet/contract drift in either theme or either fallback copy.
- Strict public appearance contract and API projection for enabled themes, locale-compatible registry fonts, size steps, defaults, and the motion-toggle flag.
- Root layout appearance source selected by `PORTFOLIO_DATA_SOURCE=database|legacy`; the former hard-coded root settings singleton and dialog option arrays are removed.
- Appearance cache keys are resource/locale scoped and cookie independent; public API and rendered HTML responses do not send `Vary: Cookie`.
- Live first-response proof covers both locale defaults and a Persian visitor cookie whose valid light/reduced/XL choices are honored while an incompatible font is corrected to the configured Vazir default.
- Live rollback and fresh cold-outage runs prove the legacy source is API-independent and unavailable database data does not synthesize owner settings.
- A pre-stream production route gate now proves appearance cold/expired failures return localized secure HTTP `503`, while healthy and in-window validated pages remain `200` and explicit legacy mode never reads the API.
