# M1 — Trusted domain and media foundation

Status: **Complete**  
Snapshot: **2026-08-14**  
Depends on: M0 repository work is available; provider revocation does not block implementation  
Roadmap: [M1 definition and exit gate](../ROADMAP.md#m1--trusted-domain-and-media-foundation)

## Outcome so far

The trusted domain and media foundation is complete. A fresh PostgreSQL 17 database accepted both reviewed migrations, including the supplemental integrity constraints; the deterministic seed then produced identical counts on two consecutive runs. Package-boundary enforcement covers both shared contracts and the web client graph, and API configuration is validated before providers or listeners start.

## Delivered

- `packages/contracts`: branded IDs, locales, Persian/English slug normalization, scalar values, pagination, errors, appearance preferences, auth, contact, frontmatter, sync state, and blog commands.
- `packages/database`: 41-model/19-enum Prisma schema, integrity constraints/partial indexes, pooled client, optimistic concurrency, advisory locks, and deterministic seed.
- `packages/markdown`: bounded safe frontmatter, deterministic serialization, GFM/directive validation, sanitize-last rendering, Shiki output, headings, reading time, and restricted inline Markdown.
- `packages/media`: private S3/MinIO and local adapters, magic-byte MIME checks, SHA-256 identity, safe names, and traversal-resistant keys.
- Security corpora cover raw HTML/XSS, unsafe URLs, YAML abuse, malformed/unknown directives, H1 rejection, heading collisions, and unknown code languages.
- Contracts include a boundary test preventing database or Node-only imports.
- The web suite rejects database dependencies anywhere in the package and server-only modules or non-public environment variables reachable from a `"use client"` entry.
- API startup validates listener, PostgreSQL, SMTP, and sender configuration without echoing credential-bearing values in errors.
