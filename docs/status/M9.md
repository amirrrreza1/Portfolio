# M9 — Operations, release, and cleanup

Status: **In progress**
Snapshot: **2026-09-06**
Depends on: M5, M8 — both complete

## Implemented

- Multi-stage non-root web, API, worker, and migration images; production-like Compose profiles; private data networks; health checks; read-only application filesystems; dropped capabilities; PID/CPU/memory limits; and a Caddy edge.
- A one-shot migration service that gates API startup, plus distinct publication, scheduler, and maintenance processes.
- Readiness now checks PostgreSQL, MinIO, and publication backlog without exposing credentials or dependency versions.
- Failed contact delivery records bounded attempts and retry timing. The maintenance worker retries with exponential backoff, leaves exhausted failures visible, and purges messages at their stored retention deadline.
- Bounded maintenance retention covers audit events, WebAuthn challenges, revoked/expired sessions, used recovery codes, stale editor drafts, import reports, contact messages, and eligible media. Failure counters promote a pass to an error-level operational event without logging message content or credentials.
- Owner-only contact listing, retry queueing, and deletion operations; dashboard counts for contact delivery, overdue retries, publication/invalidation state, and media storage. Public contact abuse controls include the browser honeypot, minimum completion time, generic suppression response, and client-key throttling.
- Expired import-report cleanup and conservative orphan cleanup for old archived or terminal media, with object-deletion failures retained for a later pass.
- Encrypted combined PostgreSQL/MinIO backup and guarded isolated-restore scripts, a content-integrity verifier, deployment/rollback, backup/restore, and incident runbooks, and an expanded bilingual release smoke command.
- MinIO bucket versioning with an app-scoped private policy, explicit egress only where needed, worker-specific secret scopes, pinned PostgreSQL/MinIO operations tooling, and a dedicated migration package.
- Shiki token styles are finite static classes under self-only style CSP, Vazir Code is physically split by script, and standalone web images discard server source maps.
- CI gates for migrations against PostgreSQL 17, generated OpenAPI drift, production dependency audit and license policy, hardened API/web/operations image builds, Trivy scans, and retained SPDX SBOMs.
- ADR-016's Next Cache Components boundary for validated public DTOs, with database mode as the production default and legacy JSON available only by explicit rollback selection.
