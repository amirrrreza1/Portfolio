# M8 — Blog authoring, publishing, and SEO

Status: **In progress**
Snapshot: **2026-08-30**
Depends on: M3, M4, M6, M7

## Delivered so far

### Slice 1 — the authoring boundary

Proven against a running stack in
[`evidence/M8-blog-authoring-live.md`](evidence/M8-blog-authoring-live.md) — 25
checks, re-runnable as `pnpm --filter @portfolio/api verify:blog`.

M3 built the article authority and M4 proved the public reads, but nothing let a
person reach either: `packages/contracts/src/blog/commands.ts` had described
every command since M3 while `publish`, `schedule`, `unpublish`, and `archive`
went unimplemented, no endpoint addressed a translation, and `PUBLISH_BLOCKERS`
was eleven constants nothing computed. This slice closes that gap.

- **Editorial state transitions as commands**, per API_SPEC §6 — publish,
  schedule, unpublish, archive — each with its own preconditions, audit event,
  and invalidation urgency, rather than one diff-driven status patch.
- **A publish checklist that is actually evaluated.** A pure evaluator in
  `@portfolio/contracts` turns gathered facts into blockers and warnings;
  blockers refuse, warnings must be acknowledged by name. `inspectArticleSource`
  in `@portfolio/markdown` reports what the render pipeline would _throw_ on, so
  the checklist can describe a body that is not ready yet.
- **Autosave** to `PostDraft` with no version check and no path to publication,
  reported to the editor beside the committed body rather than merged into it.
- **Slug history.** A slug change writes a `308` in the same transaction, and a
  second move collapses the chain instead of adding a hop.
- **Blog taxonomy CRUD** — the only way a category or tag comes into being,
  which is what makes the article store's refusal to create one implicitly safe.
- **Preview** through the production pipeline, held in memory under an
  unguessable short-lived token, never persisted.

Every transition writes an immutable revision, a redacted audit event, and a
durable invalidation outbox row inside the transaction that changed the state.

### Slice 2 — the editor

Proven in a real browser in
[`evidence/M8-editor-live.md`](evidence/M8-editor-live.md), re-runnable as
`pnpm --filter @portfolio/web test:e2e:admin -- blog-editor`.

- **`AdminBlogEditor`**, a fifth workspace panel: articles by post and locale,
  frontmatter fields, a Markdown body, the directive palette, the publish
  checklist with a checkbox per warning, and the four state transitions.
- **Autosave**, debounced, writing `PostDraft` only. A newer draft is offered
  as an explicit restore rather than merged into what the author is reading.
- **The preview route** at `/admin/blog/preview/[token]`, rendering what the
  production pipeline produced inside the same reading surface the public
  article page uses, with `noindex` in both the header and the document.
- **Slug suggestion** from the title, but only while the slug has never been
  set — an established slug is a public URL.

The run found three defects, all recorded in the evidence file: the palette
could insert a block directive mid-line, where it renders as literal text;
every `<select>` in the admin panel was announced with its own option list as
part of its accessible name, because the shared `Field` primitive wrapped its
control in the `<label>`; and a refused transition was collapsed to "check the
values you entered", discarding the blockers and warnings the API had answered
with. All three are fixed. M7's browser proof was re-run against the `Field`
change and passes unchanged.

### Slice 3 — deterministic Markdown import

Proven against real PostgreSQL and MinIO, then through the real admin browser
flow, in
[`evidence/M8-import-live.md`](evidence/M8-import-live.md). The API proof now
runs 30 checks as `pnpm --filter @portfolio/api verify:blog`; the browser proof
still uses the one continuous owner session because recovery codes are
single-use.

- **Dry run before save.** One bounded `.md`, `.markdown`, or `.mdx` upload is
  decoded as strict UTF-8, normalized deterministically, rendered through the
  production article pipeline, and returned with line-addressed findings and
  an exact diff. Missing metadata is visible as `INFERRED_*` information rather
  than invented silently.
- **MDX is data, never code.** Plain Markdown in an `.mdx` file is converted to
  canonical `.md`; imports, exports, expressions, and unmapped JSX components
  are rejected outside fenced code blocks. Raw HTML, unsafe URLs, malformed
  directives, and article-body headings that violate the contract are also
  refused before confirmation exists.
- **The original upload is retained exactly.** Its bytes are written first to
  a random, private MinIO quarantine key, with SHA-256 and byte length recorded
  in `MediaAsset`. It is never exposed by a public media path, including when
  normalization fails.
- **Confirmation is capability-bound.** Only a random report token is returned;
  PostgreSQL stores its SHA-256. The report is bound to the actor, post, locale,
  current article version, acceptance result, and expiry, and becomes unusable
  after one successful save. Confirmation calls the same validated,
  transactional article-save path as the editor.
- **Import cannot smuggle a lifecycle transition.** A new translation starts as
  `DRAFT`; an existing translation keeps its current status and publication
  timestamps. Publish, schedule, withdrawal, and archive remain explicit
  audited commands.

### Slice 4 — revisions and restore

Proven against a running stack and in a real browser in
[`evidence/M8-restore-live.md`](evidence/M8-restore-live.md). The API proof now
runs 41 checks as `pnpm --filter @portfolio/api verify:blog`.

- **The restore is the save.** `restoreArticleRevision` replays the revision's
  recorded Markdown **source** through `saveTranslation`, the transaction an
  author's own save runs, so the render, digest, reading time and heading tree
  are produced by today's renderer rather than copied out of a snapshot. What
  history contributes is the text and the metadata that were recorded;
  everything derived is derived again.
- **One restore endpoint.** `POST /admin/revisions/:id/restore` still answers
  for every resource family; an article revision is routed to the article path
  before the generic transaction opens, so rendering never happens inside a
  held write transaction.
- **A restore cannot change publication state.** Status, `publishedAt` and
  `scheduledFor` come from the row as it stands, never from the snapshot, for
  the same reason import preserves them: publishing is an audited command with
  a checklist, not a side effect of editing prose. Post-level taxonomy —
  category, tags, cover — likewise stays as it is, because it belongs to the
  post both locales share.
- **A snapshot that no longer matches its own digest is refused**, and an
  archived translation refuses the write rather than re-dating its withdrawal.
  Reading history stays available in both cases.
- **Scoped history in the editor.** `GET …/translations/:locale/revisions` and
  `…/revisions/:revisionId` return the list without the stored render, and one
  revision as the exact document a restore would write plus its diff. The
  **Version history** panel compares before it restores.
- The revision snapshot gained the SEO fields, canonical URL and social image,
  without which a restore kept today's metadata beside yesterday's prose; and
  `revisionSnapshot` stopped existing in two modules at once.

The run found one defect: moving a slug **back** to a path that already
redirected away collapsed the old rule into a redirect to itself, which
`slug_redirects_no_self_target` refused mid-transaction. The destination's own
rule is now cleared before chains are collapsed.

## The defect the live run found

`archive` enqueued an invalidation whose `reason` the signed-event contract does
not define, and every archive failed with a `500` inside its transaction. The
lifecycle module had declared the reason union by hand and added a value the
contract lacked; TypeScript was satisfied because the local type was internally
consistent. The type is now derived from the contract, and archive enqueues
`unpublish` — accurate, because archiving has no cache behaviour of its own.

The same run found that the failure was undiagnosable: the exception filter
answered `500` and logged nothing. It now logs the stack for any unmapped
exception.
