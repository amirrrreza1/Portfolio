# M8 — Blog authoring, publishing, and SEO

Status: **Complete** — all seven slices implemented and verified
Snapshot: **2026-09-04**
Depends on: M3, M4, M6, M7

## Delivered

### Slice 1 — the authoring boundary

Proven against a running stack in
[`evidence/M8-blog-authoring-live.md`](evidence/M8-blog-authoring-live.md) — 25
checks, re-runnable as `pnpm --filter @portfolio/api verify:blog`.

M3 built the article authority and M4 proved the public reads, but nothing let a
person reach either: `packages/contracts/src/blog/commands.ts` had described
every command since M3 while `publish`, `schedule`, `unpublish`, and `archive`
went unimplemented, no endpoint addressed a translation, and `PUBLISH_BLOCKERS`
was eleven constants nothing computed. This slice closes that gap.

- **Editorial state transitions as commands**, per API_SPEC §6 — publish,
  schedule, unpublish, archive — each with its own preconditions, audit event,
  and invalidation urgency, rather than one diff-driven status patch.
- **A publish checklist that is actually evaluated.** A pure evaluator in
  `@portfolio/contracts` turns gathered facts into blockers and warnings;
  blockers refuse, warnings must be acknowledged by name. `inspectArticleSource`
  in `@portfolio/markdown` reports what the render pipeline would _throw_ on, so
  the checklist can describe a body that is not ready yet.
- **Autosave** to `PostDraft` with no version check and no path to publication,
  reported to the editor beside the committed body rather than merged into it.
- **Slug history.** A slug change writes a `308` in the same transaction, and a
  second move collapses the chain instead of adding a hop.
- **Blog taxonomy CRUD** — the only way a category or tag comes into being,
  which is what makes the article store's refusal to create one implicitly safe.
- **Preview** through the production pipeline, held in memory under an
  unguessable short-lived token, never persisted.

Every transition writes an immutable revision, a redacted audit event, and a
durable invalidation outbox row inside the transaction that changed the state.

### Slice 2 — the editor

Proven in a real browser in
[`evidence/M8-editor-live.md`](evidence/M8-editor-live.md), re-runnable as
`pnpm --filter @portfolio/web test:e2e:admin -- blog-editor`.

- **`AdminBlogEditor`**, a fifth workspace panel: articles by post and locale,
  frontmatter fields, a Markdown body, the directive palette, the publish
  checklist with a checkbox per warning, and the four state transitions.
- **Autosave**, debounced, writing `PostDraft` only. A newer draft is offered
  as an explicit restore rather than merged into what the author is reading.
- **The preview route** at `/admin/blog/preview/[token]`, rendering what the
  production pipeline produced inside the same reading surface the public
  article page uses, with `noindex` in both the header and the document.
- **Slug suggestion** from the title, but only while the slug has never been
  set — an established slug is a public URL.
- **Portable export** downloads the latest saved translation as deterministic
  UTF-8 Markdown with frontmatter. It excludes unsaved edits/autosaves, checks
  source integrity, preserves lifecycle, and never falls back across locales.
  Its authenticated no-store attachment, import compatibility, and browser
  download are proven in the final discovery report (§11 of the live API proof).

The run found three defects, all recorded in the evidence file: the palette
could insert a block directive mid-line, where it renders as literal text;
every `<select>` in the admin panel was announced with its own option list as
part of its accessible name, because the shared `Field` primitive wrapped its
control in the `<label>`; and a refused transition was collapsed to "check the
values you entered", discarding the blockers and warnings the API had answered
with. All three are fixed. M7's browser proof was re-run against the `Field`
change and passes unchanged.

### Slice 3 — deterministic Markdown import

Proven against real PostgreSQL and MinIO, then through the real admin browser
flow, in
[`evidence/M8-import-live.md`](evidence/M8-import-live.md). The API proof now
runs 30 checks as `pnpm --filter @portfolio/api verify:blog`; the browser proof
still uses the one continuous owner session because recovery codes are
single-use.

- **Dry run before save.** One bounded `.md`, `.markdown`, or `.mdx` upload is
  decoded as strict UTF-8, normalized deterministically, rendered through the
  production article pipeline, and returned with line-addressed findings and
  an exact diff. Missing metadata is visible as `INFERRED_*` information rather
  than invented silently.
- **MDX is data, never code.** Plain Markdown in an `.mdx` file is converted to
  canonical `.md`; imports, exports, expressions, and unmapped JSX components
  are rejected outside fenced code blocks. Raw HTML, unsafe URLs, malformed
  directives, and article-body headings that violate the contract are also
  refused before confirmation exists.
- **The original upload is retained exactly.** Its bytes are written first to
  a random, private MinIO quarantine key, with SHA-256 and byte length recorded
  in `MediaAsset`. It is never exposed by a public media path, including when
  normalization fails.
- **Confirmation is capability-bound.** Only a random report token is returned;
  PostgreSQL stores its SHA-256. The report is bound to the actor, post, locale,
  current article version, acceptance result, and expiry, and becomes unusable
  after one successful save. Confirmation calls the same validated,
  transactional article-save path as the editor.
- **Import cannot smuggle a lifecycle transition.** A new translation starts as
  `DRAFT`; an existing translation keeps its current status and publication
  timestamps. Publish, schedule, withdrawal, and archive remain explicit
  audited commands.

### Slice 4 — revisions and restore

Proven against a running stack and in a real browser in
[`evidence/M8-restore-live.md`](evidence/M8-restore-live.md). The API proof now
runs 41 checks as `pnpm --filter @portfolio/api verify:blog`.

- **The restore is the save.** `restoreArticleRevision` replays the revision's
  recorded Markdown **source** through `saveTranslation`, the transaction an
  author's own save runs, so the render, digest, reading time and heading tree
  are produced by today's renderer rather than copied out of a snapshot. What
  history contributes is the text and the metadata that were recorded;
  everything derived is derived again.
- **One restore endpoint.** `POST /admin/revisions/:id/restore` still answers
  for every resource family; an article revision is routed to the article path
  before the generic transaction opens, so rendering never happens inside a
  held write transaction.
- **A restore cannot change publication state.** Status, `publishedAt` and
  `scheduledFor` come from the row as it stands, never from the snapshot, for
  the same reason import preserves them: publishing is an audited command with
  a checklist, not a side effect of editing prose. Post-level taxonomy —
  category, tags, cover — likewise stays as it is, because it belongs to the
  post both locales share.
- **A snapshot that no longer matches its own digest is refused**, and an
  archived translation refuses the write rather than re-dating its withdrawal.
  Reading history stays available in both cases.
- **Scoped history in the editor.** `GET …/translations/:locale/revisions` and
  `…/revisions/:revisionId` return the list without the stored render, and one
  revision as the exact document a restore would write plus its diff. The
  **Version history** panel compares before it restores.
- The revision snapshot gained the SEO fields, canonical URL and social image,
  without which a restore kept today's metadata beside yesterday's prose; and
  `revisionSnapshot` stopped existing in two modules at once.

The run found one defect: moving a slug **back** to a path that already
redirected away collapsed the old rule into a redirect to itself, which
`slug_redirects_no_self_target` refused mid-transaction. The destination's own
rule is now cleared before chains are collapsed.

### Slice 5 — discovery and SEO

Proven on 2026-08-31 in
[`evidence/M8-discovery-live.md`](evidence/M8-discovery-live.md): the 63-check
live API proof, all 45 public browser tests (including 10 discovery tests),
and both real-stack admin regression flows passed.

M4 delivered the article page's own canonical, `hreflang`, and JSON-LD. What
was missing was everything a reader or a crawler uses to _find_ an article, and
the read models those surfaces need.

- **Three new public read models**, per API_SPEC §4: `…/blog/categories/:slug`
  and `…/blog/tags/:slug` for the taxonomy pages, and `…/blog/feed-index` for
  the ordered entries a feed and a sitemap are generated from. A fourth,
  `…/blog/taxonomy`, is an addition to the spec and is documented there: the
  navigation index and the sitemap both need to _enumerate_ terms, which no
  endpoint in the original table could do.
- **All of them exclude what the listing excludes.** The published,
  unarchived, digest-matching, current-renderer predicate is one constant
  spread into every discovery query, and the per-row integrity check runs on
  each page after it is sliced — so a corrupted article disappears from the
  feed, the sitemap, and its category page together, rather than from some of
  them.
- **A withdrawn term is a `404`, not an empty page.** An empty category page is
  crawlable and outlives the editorial decision that withdrew it.
- **One alternate list, two consumers.** Feed entries and taxonomy rows carry
  the same `alternates` set the article detail response carries, including the
  current locale. The sitemap's `xhtml:link` group and the page's `hreflang`
  group are therefore generated from one list rather than from two that happen
  to agree — and the browser proof compares them.
- **Category and tag pages** at `/[locale]/blog/(category|tag)/[slug]`, one
  implementation behind two thin route files, with breadcrumbs, `CollectionPage`
  and `BreadcrumbList` structured data, reciprocal `hreflang`, and the same
  `503` gate every other public document route goes through.
- **Pagination** by cursor. A cursor names a row rather than a page, so a
  cursor URL's contents shift as articles are published above it: those pages
  are `noindex, follow`, self-canonical, and absent from the sitemap, while the
  first page stays a stable canonical URL.
- **Per-locale RSS** at `/[locale]/blog/feed.xml`, **per-locale sitemaps** at
  `/[locale]/sitemap.xml` behind a sitemap index at `/sitemap.xml`, and
  **`robots.txt`** naming that index and blocking nothing a renderer needs. The
  proxy's blanket `private, no-store` is lifted for exactly these paths, which
  are identical for every visitor.
- **Social images** resolved on the server — the translation's own image first,
  the post-level cover second — and served as bytes by
  `…/blog/posts/:slug/image`, gated on the article being publicly readable. An
  English article with no authored image receives a generated 1200×630 share
  card from `/{locale}/blog/{slug}/share-image`; RTL generation is deliberately
  refused until the renderer can shape Persian correctly. The card type follows
  the content: `summary_large_image` only when an image actually exists.
- **Related articles** selected by declared category and tags alone, with a
  shared category outranking a shared tag and recency breaking ties. No visitor
  signal enters the selection, and an article with nothing in common yields an
  empty block rather than padding.

### Slice 6 — the scheduled-publication test matrix

Proven on 2026-08-31 in
[`evidence/M8-publication-live.md`](evidence/M8-publication-live.md). The live
matrix now also injects a final audit failure after actual PostgreSQL writes,
and the scheduler/publication lock retains one checked-out session throughout
the worker callback instead of using independent pooled queries.

- **Single scheduler.** `runUnderExclusiveLock` was extracted from the worker's
  process entrypoint so the topology rule is testable without a server: a
  replica that cannot take the advisory lock does not run the work, it waits
  and asks again. `packages/database` proves the key derivation is identical in
  every process, stays inside PostgreSQL's signed 64-bit range, and that the
  lock is released even when the work throws. Exclusion between two real
  sessions is a server behaviour and is proven against a running PostgreSQL in
  `verify:blog` §10.
- **Retry idempotency.** The scheduler is a poll, so a due translation is seen
  on every tick until it is published; `enqueueDuePublications` collapses that
  into one pending job, proven against real PostgreSQL under PGlite. And the
  case that actually loses data — the worker commits the publication and dies
  before settling the job — is proven to be a no-op on the retry: no second
  revision, no second outbox row, and above all no re-dated `publishedAt`.
- **Transactional rollback.** The unit test proves the publish path performs
  every write inside the one transaction it opens, so nothing can survive a
  rollback; that a real PostgreSQL actually rolls back is proven live in
  `verify:blog` §10, which fails a scheduled publication inside its transaction
  and asserts the row is still `SCHEDULED` with no revision and no outbox row.

## The defect the live run found

`archive` enqueued an invalidation whose `reason` the signed-event contract does
not define, and every archive failed with a `500` inside its transaction. The
lifecycle module had declared the reason union by hand and added a value the
contract lacked; TypeScript was satisfied because the local type was internally
consistent. The type is now derived from the contract, and archive enqueues
`unpublish` — accurate, because archiving has no cache behaviour of its own.

The same run found that the failure was undiagnosable: the exception filter
answered `500` and logged nothing. It now logs the stack for any unmapped
exception.

## Five additional defects found by the independent close-out run

1. **`next build` type-checks what `tsc -p tsconfig.json` does not.** Two
   `alternates.push({ hreflang: "x-default" })` calls were errors under the
   build's configuration alone, because the array's element type had been
   inferred from a `Locale` map. Both arrays are annotated now. The build also
   checks test files, which a later assertion tripped over.
2. **Four lint errors in code that had never been linted** — two
   `unknown | null` return types and two unused `_sortOrder` bindings this
   configuration does not exempt.
3. **Three specs asserted `en-US` and `fa-IR`.** The site defines one language
   tag per locale (`bcp47`, I18N.md §6), and it is the value `lang`, `hreflang`,
   the feed's `<language>` and JSON-LD's `inLanguage` all read. The assertions
   were corrected to the contract.
4. **`toArticleSitemapUrl` derived `loc` from `entry.slug`** instead of from the
   alternate group for the locale it was given — identical in normal use, and a
   `loc` in the wrong language the first time a caller paired the two loosely.
5. **An article whose author chose no image advertised no `og:image` at all**,
   against SEO.md §3.

### Slice 7 — the generated share card

Closing that last defect: `/{locale}/blog/{slug}/share-image` renders a
1200×630 PNG from the article's own title, date and author on the site's dark
palette, read from `THEME_TOKENS` rather than spelled as hex — THEMING.md §3
applies to a card as much as to a component. `buildPublicArticleMetadata` points
`og:image` at the author's social image or cover when there is one and at this
route when there is not, so every article has a share image with declared
dimensions and alt text, and the route and the metadata read one predicate.

satori reads TTF and OTF only, so `apps/web/src/assets/og` carries TTF copies of
the faces the card uses and `next.config.ts` traces them into the standalone
output.

## Known limitations

- **No generated share card for Persian.** satori lays out glyphs without a text
  shaper: no Arabic joining, no bidi reordering. A Persian card was rendered,
  inspected and rejected — disconnected letters in visual order is worse than no
  card, because it is what every reader who shares the article sees.
  `canGenerateShareCard` returns false for RTL locales; a Persian article uses
  the author's chosen image, or none. Closing this means shaping the text before
  it reaches satori, and it is a slice of its own.
- **Pagination is by cursor, not page number.** Cursor pages are
  `noindex, follow`, self-canonical and absent from the sitemap, and the first
  page is a stable canonical URL. Numbered archive pages would be a different
  design decision, not a bug fix.
- **Nothing is served from a shared cache**, carried from M4. The new surfaces
  set `s-maxage` and are exactly the traffic a shared cache should absorb, which
  gives the Next 16 caching ADR a second reason to exist.
