# M6 — Authentication foundation

Status: **Complete**  
Snapshot: **2026-08-27**  
Depends on: M1  
Roadmap: [M6 definition and exit gate](../ROADMAP.md#m6--authentication-foundation)

## Outcome

The admin boundary is closed and proven, end to end, in a real browser. All ten
API_SPEC §5 endpoints answer; a two-factor login issues an opaque rotating
session; passkey assertions are verified cryptographically with origin, RP ID,
replay and counter enforcement; recovery works and sweeps other sessions; the
authenticated shell cannot be reached without a verified session; and the owner
recovery and credential-revocation drill is written and rehearsed.

The shell manages **security state and nothing else** — identity, sessions,
passkeys. That is the whole surface the gate permits ("no content mutation
capability until the gate passes"), and there are no `/admin` resource
endpoints to mutate content with in any case. ADMIN-003's dashboard defers to
M7 with the endpoints it would read.

## Delivered

- Opaque keyed session and CSRF token primitives, Argon2id hashing, hashed
  single-use recovery codes, single-use WebAuthn challenges, and cookie-mutation
  guards in [`packages/auth-core`](../../packages/auth-core).
- Explicit-apply owner provisioning gated by bootstrap file and expiry, **now
  issuing the recovery codes the bootstrap depends on**.
- **The API auth boundary** (`apps/api/src/modules/auth/`): CSRF rotation,
  password step, WebAuthn options/verify, passkey enrolment, recovery, session
  read, re-authentication, logout, session listing, and session revocation.
- **Full WebAuthn verification** through `@simplewebauthn/server`: origin and
  RP ID binding, single-use challenges, user-verification requirement,
  signature verification, and signature-counter regression handling with an
  owner notification.
- **The authenticated admin shell** (`apps/web/src/app/admin/`): sign-in,
  recovery sign-in, actor identity, the ADMIN-002 session list with revocation
  and a passkey re-authentication prompt, passkey enrolment, and sign-out.
  Guarded by [`admin-session.ts`](../../apps/web/src/server/admin-session.ts),
  which asks the API on every render and believes nothing else.
- **Admin-specific CSP and security headers** in
  [`proxy.ts`](../../apps/web/src/proxy.ts): stricter than the public policy in
  every clause it changes, plus `X-Robots-Tag: noindex, nofollow, noarchive`,
  `Referrer-Policy: no-referrer`, COOP/CORP/COEP, and a permissions policy that
  names WebAuthn explicitly.
- **Deny-by-default authorization** (`authorization.ts`): an allowlist encoding
  API_SPEC §9, a recent-auth requirement on session-wide and destructive
  permissions, and an object-level ownership check.
- Structured audit events for every security-relevant action, written through a
  path that cannot turn a failed audit write into a failed refusal.
- An operator command for credential revocation,
  [`revoke-credentials.ts`](../../packages/database/scripts/revoke-credentials.ts),
  which removes a passkey and sweeps every session in one transaction and
  refuses the lockout case.
- A software WebAuthn authenticator
  (`apps/api/scripts/software-authenticator.ts`) so the passkey path is tested
  against real ES256 signatures rather than a stubbed verifier.
- 27 auth unit tests in [`apps/api/test/auth.spec.ts`](../../apps/api/test/auth.spec.ts),
  25 boundary unit tests in
  [`apps/web/test/admin-boundary.spec.ts`](../../apps/web/test/admin-boundary.spec.ts)
  and [`admin-session.spec.ts`](../../apps/web/test/admin-session.spec.ts), and
  three committed live proofs.

## Three defects the browser run found

Recorded in full in [the shell evidence](evidence/M6-admin-shell-live.md); in
short:

1. **Provisioning issued no recovery codes**, so a freshly provisioned owner
   could never sign in — login needs a passkey, enrolling one needs a session,
   and the only session without a passkey comes from a code. `issueRecoveryCodes`
   existed, fully tested, and was called by nothing.
2. **`webAuthnRegistrationSchema` rejected every real browser**, because it is
   `.strict()` and did not list `authenticatorAttachment`. All 27 unit tests and
   all 24 live API checks passed anyway: the software authenticator builds its
   payload by hand and never sent the field.
3. **A relying-party ID may not be an IP address.** Chrome refuses
   `rp.id: "127.0.0.1"` before consulting any authenticator; the software
   authenticator has no such rule.

All three share a shape worth naming: _a test double built from the same
understanding as the code agrees with it by construction._ The auth slice
already recorded one instance (a doubly-encoded challenge the unit tests could
not see, because they read the value from the same place the verifier did).
These are three more, and it took a browser to see each of them.

## The editor-permission decision is still owed

`EDITOR` is defined in the type system and its unambiguous permissions are
recorded, but `isRoleAssignable()` refuses to grant it. API_SPEC §9's editor
column still reads "configurable" and "no by default", and DECISIONS.md lists
the v1 editor-permission matrix as an owner decision that is overdue. Encoding a
guess would turn an open question into shipped behaviour nobody chose;
deny-by-default already means every unlisted permission is refused, so the
restriction costs nothing until the ADR lands. Provisioning stays owner-only in
the meantime, exactly as that decision requires.

This does not hold the gate. It holds M7's editor story.

## Carried into M7

  counts, failed-login events — with the `/admin` endpoints that would feed it.
- `style-src 'unsafe-inline'` on the admin policy, inherited from the shared
  stylesheet. SECURITY.md §10 requires component inline styles to be removed
  repository-wide rather than allowed; until that lands the admin policy cannot
  be tighter than the sheet it shares.
- A UI for listing and revoking passkeys. Revocation today is the operator
  command, which is the correct trust level for removing a credential but is
  not a substitute for the owner being able to _see_ what is registered.
