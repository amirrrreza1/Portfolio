# Blog language model

The portfolio and shared site interface are English-only. Multilingual behavior belongs exclusively to blog content. Article persistence still follows [ADR-005](DECISIONS.md#adr-005--bilingual-articles-as-per-locale-translations-of-one-post): one stable post can have independently authored and published language versions.

## Supported blog languages

| Key  | Language | Content direction | Default reading font |
| ---- | -------- | ----------------- | -------------------- |
| `en` | English  | `ltr`             | JetBrains Mono       |
| `fa` | Persian  | `rtl`             | Shabnam              |

This is a closed, code-reviewed allowlist. Adding a blog language requires slug, font, typography, sanitization, SEO, and test coverage.

## URL policy

Portfolio URLs have no locale prefix:

```text
/
/projects
/projects/<slug>
```

Blog URLs identify the language of the content:

```text
/en/blog
/fa/blog
/en/blog/<slug>
/fa/blog/<slug>
/<language>/blog/category/<slug>
/<language>/blog/tag/<slug>
```

`/blog` redirects permanently to `/en/blog`. Old site-wide locale URLs such as `/en`, `/fa`, `/en/projects`, and `/fa/projects` redirect permanently to the corresponding unprefixed English portfolio URL. Browser `Accept-Language` and the retired `portfolio_locale` cookie do not redirect the home page.

## Reader behavior

- The header, footer, navigation, appearance dialog, portfolio content, and portfolio metadata are always English.
- The blog index contains the blog-language selector.
- A blog route marks its content container with the selected language and direction. Persian content is RTL without changing the English site chrome.
- An article offers another language only when that version is published. Missing versions never fall back to another language under the requested URL.
- Blog font and size preferences remain reading-surface settings; language is not an appearance setting.

## Author behavior

- The blog workspace asks the author to choose English or Persian when starting or importing an article.
- Each language version has its own title, slug, excerpt, SEO fields, Markdown, revisions, schedule, and publication state.
- Portfolio CMS forms expose English content only. Site settings save `en` as the sole enabled portfolio locale.
- Existing Persian portfolio rows may remain in storage for rollback/history, but public portfolio reads and authoring do not expose them.

## Direction and formatting

- The root document and shared chrome use `lang="en"` and `dir="ltr"`.
- Blog content uses the language definition for its nested `lang` and `dir` attributes.
- Code blocks remain LTR. Shared layout uses logical CSS properties so RTL article content does not distort surrounding controls.
- Dates are stored as UTC and formatted for the blog content language. Machine-readable values stay ISO 8601.

## SEO and discovery

- Portfolio canonicals are unprefixed and have no language alternates.
- Blog index, taxonomy, feed, and article URLs retain explicit language prefixes.
- Reciprocal `hreflang` is emitted only for real blog language variants; `x-default` points to the English blog version when it exists.
- The English sitemap contains `/`, `/projects`, English projects, and English blog URLs. The Persian sitemap contains Persian blog URLs only.
- `BlogPosting.inLanguage`, titles, descriptions, and publication dates come from the requested article version.

## Verification

Automated coverage must prove:

- `/` stays English regardless of browser language or stale locale cookies;
- old localized portfolio URLs redirect in one hop to unprefixed URLs;
- `/en/blog` and `/fa/blog` remain independently readable;
- Persian blog content is RTL while shared site chrome stays English/LTR;
- authoring can start and import either blog language;
- missing article versions do not fall back;
- portfolio sitemap entries are unprefixed and Persian discovery contains no portfolio pages.
